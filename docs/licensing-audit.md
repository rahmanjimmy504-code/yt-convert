## 1. Contributors

### 1.1 What the history shows

| `arena-ai-coding-agent[bot]` | 8 | Automated / AI agent |

| `Arena Agent <arena@example.com>` | 1 | Automated / AI agent |

Pull-request authorship (the stronger signal, because PRs are squash-merged so the *merge* commit carries the human's name while the *PR* records the real author):

- A large majority of the 60+ merged PRs (#2–#64) are authored by **`app/arena-ai-coding-agent`**.
- A small number are authored directly by `rahmanjimmy504-code`.

### 1.2 Why this matters

- The project has **one human contributor** (`rahmanjimmy504-code`), who is also the repository owner.
- A substantial portion of the codebase — essentially every feature beyond the initial scaffold — was **authored by a non-human AI coding agent** (`arena-ai-coding-agent` / `Arena Agent`), operating under the human's direction through Arena.ai's Agent Mode.
- There is **no** `CONTRIBUTING.md`, no Developer Certificate of Origin (DCO) check, no `AUTHORS` file, and no contributor licence agreement (CLA) in the repository.
- The working checkout's `git` history has been squashed to a single commit, which hides authorship inside the clone even though GitHub retains the full record.

### 1.3 Assessment

Whether the human owner holds the copyright in code generated by the AI agent is **legally unsettled**:

- Under current U.S. guidance and case law (e.g. *Thaler v. Perlmutter*, USCO AI guidance), material generated by AI **without sufficient human authorship is not copyrightable**.
- AI-**assisted** works can be copyrightable, but only to the extent of the human's own creative contribution, and the boundary is fact-specific and contested.
- The AI agent (`arena-ai-coding-agent`) is not a natural person who can grant a copyright licence; any licence it purports to "give" is not enforceable.

Because a meaningful fraction of the code cannot be confidently attributed to the single human copyright holder, **contributor rights are unclear**. Re-licensing the whole work under GPL-3.0-or-later now would risk a licence that the owner is not actually entitled to grant.

**This is a blocker. Per the audit rule, the licence must not be changed while this is unresolved.**

### 1.4 How to clear the blocker (options, for a follow-up)

1. **Attestation of authorship/ownership** — the owner documents (in-repo, e.g. `AUTHORS` + `CONTRIBUTING.md`) that they directed the AI agent and assert ownership of the resulting code, ideally with a DCO sign-off on all commits.
2. **Identify and exclude/rewrite AI-authored portions** — mechanically separate the files whose provenance cannot be established, and keep only human-attested code under the new licence.
3. **Obtain legal advice** — for a project contemplating redistribution under copyleft terms, an actual lawyer's sign-off on the AI-authorship question is the only way to be *sure*.

> Only after one of these is done should the GPL-3.0-or-later relicense PR (a separate PR) be opened.

## 6. What the (still-pending) relicense PR must contain

When the blocker is cleared, the relicense PR should:

1. Replace the `For personal use only` notice (README + footer/legal strings in `src/`) with `GPL-3.0-or-later`.
2. Add the full GPL-3.0 text as `LICENSE` (and the "or later" notice, GPL-3.0-only + `or-later` SPDX).
3. Set package metadata licence fields (`package.json` → `"license": "GPL-3.0-or-later"`, `"private": false` if redistribution is intended) for both the root and `po-token-server`.
4. Add `THIRD_PARTY_NOTICES.md` covering the dependencies, the Geist font (OFL 1.1), and the Snapchat trademark.
5. Add `CONTRIBUTING.md` with a DCO-style contribution term (and `AUTHORS`/copyright attribution).
6. Update legal-page copy where it currently conflates "personal use" of the *service* with the *software* licence.
